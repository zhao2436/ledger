# 小账本

微信 / 支付宝账单的本地记账工具。网页形态，手机上能加到主屏幕，当 App 用。

- 导入微信、支付宝导出的账单（csv 或原样 zip），自动分类
- 月度收支、分类占比、毛额/净额两种口径
- 明细里逐条改分类，改了会记住
- 数据只存在你这台设备的浏览器里，不上传服务器

## 手机上怎么打开

三种方式，按方便程度排：

**1. 局域网（最快，适合先试用）**

在 Mac 上进入本目录，起一个静态服务：

```bash
python3 -m http.server 8765
```

手机连同一个 Wi-Fi，浏览器打开 `http://<Mac 的局域网 IP>:8765`。
缺点是 Mac 关机就不能用了，而且 `http://` 下不能装成 App（Service Worker 需要 https）。

**2. 托管到静态站点（推荐长期用）**

把这个目录（`ledger/` 整个）传到任意静态托管：GitHub Pages、Vercel、Netlify、Cloudflare Pages 都行，不需要构建步骤。拿到 https 地址后：

- iPhone：Safari 打开 → 分享 → 添加到主屏幕
- Android：Chrome 打开 → 菜单 → 安装应用

之后有网就能开，第二次起会走缓存，弱网也能用。

**3. 电脑上用**

直接双击 `index.html` 也能开，但 `file://` 下没有 Service Worker，部分浏览器还会限制 localStorage，建议用上面两种。

## 导入账单

微信：我 → 服务 → 钱包 → 账单 → 常见问题 → 下载账单 → **用于个人对账**，填邮箱。
支付宝：我的 → 账单 → 右上角 … → 开具交易流水证明 → **用于个人对账**，填邮箱。

两封邮件里都是 zip。把 zip 原样传到「导入」页就行，不用解压；也可以解压后只选里面的 csv。

- 同一条记录（按来源 + 交易单号）只会进一次，重复导入不会翻倍
- 支付宝的「交易分类」会直接映射过来，微信没有分类，靠关键词规则猜
- 「不计收支」的转账、提现会记为「不计」，不参与收支合计

> 这份公开部署里**不包含**你的历史账单数据（`seed/` 已在本地被排除），仓库里只有代码。历史数据请用「导入」选择自己的 JSON 备份，或在本地版本里使用。

## 分类规则

在 `parser.js` 顶部的 `RULES` 里，一条是 `[正则, 分类名]`，越靠前优先级越高。想加规则，比如「瑞幸算咖啡」，在餐饮那条正则里加上 `瑞幸` 即可。

`ALIPAY_CAT` 是支付宝自带分类到本工具分类的映射表，改这里能调整支付宝账单的归类。

## 数据在哪

浏览器的 localStorage，键名 `ledger.v1.transactions`。也就是说：

- 换浏览器、换手机、清缓存，数据就没了 —— **定期用「导出 JSON 备份」存一份**
- 备份文件可以直接在「导入」里读回来

## 文件说明

| 文件 | 作用 |
| --- | --- |
| `index.html` | 页面结构 |
| `style.css` | 样式，移动端优先 |
| `parser.js` | 账单解析 + 分类规则（无依赖） |
| `app.js` | 界面逻辑、统计、导入导出 |
| `sw.js` | 离线缓存 |
| `manifest.webmanifest` | 装成 App 用的配置 |
| `seed/` | 之前的微信历史数据 |

## 已知限制

- 微信「交易明细证明」的 PDF 不支持在网页里解析，请用「用于个人对账」的 csv 版本；PDF 可以用仓库里另一个 `money-tracker/` 的桌面脚本处理
- 退款按到账时间冲减，不跟原订单做精确配对
- 分类靠关键词，冷门商户可能落到「其他」，明细里手动改就行
